# 编辑器与文档格式（v1）

本文描述 ZestLoomer v1 作品格式与编辑器行为。日常操作见 [使用指南](USER-GUIDE.md)。

## 工作区与编辑器

Electron + Vue 3 保留。五种文档统一由 `TextEditor.vue` 使用 CodeMirror 6 编辑，不加载 Markdown 语言、语法着色、富文本或 HTML 粘贴处理。正文使用 `.cm-line` 的 `text-indent: 2em` 实现首行视觉缩进，折行不额外增加空格；内容文件不包含该显示设置。

只提供字体、字号、行高。文内查找匹配、选区可以临时高亮，这些标记不写入文件。Ctrl+F / Ctrl+H 仅处理当前打开文档，不调用 Agent 或模型。回收站只有查找，没有替换。

2026-10-06 补充：正文的 Enter 和 Shift+Enter 均插入两个换行符，保留文档已有的 LF／CRLF 格式，不向文本添加缩进空格；每个逻辑段落首行强制显示 `2em` 缩进，自动折行沿用正常左边距。Markdown 编辑页仍使用单换行与零缩进。载入和粘贴原文不会自动改写原有换行。

正文支持人物名称与别名（淡黄色）、设定标题与别名（淡绿色）的视口高亮，较长名称优先匹配，同名时人物优先。默认开启，工具栏可切换，偏好按作品保存在应用工作区设置。别名支持显式的“别名：白衣客、陆先生”等字段、迁移保留的来源记录及 YAML aliases 列表；不要求文档使用固定模板。改名、编辑资料、回收和切换作品后更新词条，回收条目不参与匹配。装饰标记仅用于显示，不写入正文，也不进入撤销历史。

每份文档拥有独立 `DocumentSession`。编辑器状态通过弱引用缓存序列化的撤销记录、选区与滚动位置，切换至空分区再返回也可恢复，且不会保留已销毁界面的事件回调。关闭应用后恢复最近作品与文档；撤销历史不跨应用重启保存。

## 文件布局

```text
ZestLoomer-xxxxxxxx/
├─ book.json                        # format: 1、书籍 ID 与标题
├─ chapters/
│  ├─ order.json                    # 可选，正文顺序的一次性原子更新
│  └─ doc_<uuid>/
│     ├─ meta.json                  # ID、类型、标题、顺序、时间与版本代数
│     └─ content.txt                # 正文原始文本
├─ characters/doc_<uuid>/
│  ├─ meta.json
│  └─ content.md                    # 人物源码，无强制区块
├─ settings/doc_<uuid>/…
├─ outlines/
│  ├─ order.json                    # 平铺大纲顺序
│  └─ doc_<uuid>/…
├─ notes/doc_<uuid>/…                # 多份独立速记
└─ .workspace/
   ├─ recovery/doc_<uuid>.json       # 恢复草稿、基准版本与时间
   └─ trash/<kind>/doc_<uuid>/…      # 按五类隔离，保留元数据与正文
```

目录与 ID 不随标题改名而变化；标题不能包含换行。资料正文只包含用户编辑的 Markdown 源码，身份信息在相邻 `meta.json`，不要求用户维护 YAML 或专用区块标记。

`kind` 为 chapters、notes、characters、settings、outlines。单篇普通导出只导出 `content.txt` / `content.md`，不附加内部身份字段。全书正文导出按正常章节顺序拼接标题和内容，不包含回收站或资料；完整备份包含分类回收站和恢复草稿，并比较全部复制文件的字节内容。

## 保存与恢复

- 停止输入 650 毫秒后保存，Ctrl+S 立即保存。每次编辑另写恢复草稿。
- 主进程按书串行调度保存、回收、恢复和备份，避免同一作品的操作互相覆盖。
- 版本为文档元数据、回收状态与正文的 SHA-256。写入前检查调用方基准版本；外部改写造成冲突时保留人的输入。
- 保存先写 `pending.json`，其中包含旧内容摘要与待提交内容、元数据；再逐个原子替换正文与元数据。下次读取可重放中断事务。
- 如果中断期间外部再次改写正文，事务恢复停止并报告冲突，不强行覆盖。
- 只有被确认写入的快照才标记为已保存。等待期间的新输入继续保留为未保存，后续再写。
- 冲突界面同时展示人的输入和当前磁盘版本。人可选择采用磁盘内容，或明确以当前输入生成新版本；再次保存仍校验版本。
- 应用关闭前请求界面完成保存；失败或冲突时保持窗口打开，提示处理。崩溃后的恢复依赖已成功落盘的草稿和事务，不承诺恢复最后一次尚未送达磁盘的按键。

恢复草稿记录自己的基准版本。基于旧版本的草稿即使继续输入，也不能自动改成基于新版本，避免重启后绕过冲突检查。

## 排序与分类回收站

正文与大纲使用平铺列表。排序文件独立原子写入，不通过重命名文件改变顺序；速记按更新时间降序，时间相同时按 ID 稳定排序。人物和设定按创建顺序显示。

移入回收站通过同一作品目录内的文档文件夹重命名完成。内容、标题、ID 和顺序信息保留；回收与恢复推进版本代数，回收前的旧提案即使恢复后也不能直接写入。

恢复沿用排序文件中仍存在的位置；若该 ID 在回收期间的重排中被移出排序文件，则按原创建顺序排在当前显式排序之后。该规则确定且可重复。

本阶段没有永久删除接口、清空按钮和自动过期清理。回收站不可编辑；排队的旧写入会因回收状态或版本改变而失败，不会复活文档。

## 引用与人的工具 / Agent 边界

引用源码形如 `[[character:doc_<uuid>|人物名]]`，同理支持 chapter、setting、outline、note。通过插入引用面板选择文档，或直接编辑引用文本。Ctrl+点击按稳定 ID 打开目标；目标已回收时切入对应分类回收站并提示只读。

`DocumentStore.agentDocuments` 返回正常文档目录，排除回收站；`agentRead` 默认拒绝读取回收内容，只有显式引用读取才能返回带回收状态的快照。Agent 通过此边界接入读取、文字检索、模型调用与提案审阅。人的回收与恢复 API 没有作为 Agent 工具暴露。

## 当前限制

- 打开作品使用当前 ZestLoomer v1 格式。
- 未实现分卷管理、复杂标签筛选或父子大纲；工作区和 Agent 均提供书内文字检索。
- 外部修改在重新打开或保存时核对；尚未提供实时文件监听。
- 标题和资料内容可随时保存，不提供内容确定性状态；未确定构想鼓励放在速记。

## 2026-10-02 Agent 与模板阶段补充

人物、设定新建时可选基础模板或空白，初始内容原子写入；无强制区块、YAML 或内容状态。人物／设定作为作者当前采用的资料，尚未确定的构想鼓励放在速记，不通过 confirmed 或 planned 字段管理。

完整备份现在同时覆盖 `.workspace/conversations/`、`proposals/`、`indexes/` 中的会话、提案及可重建索引。应用级 Agent 配置和系统加密后的密钥不在作品目录中。Agent 写入、接受与撤销通过现有按书队列及事务，普通文档格式和稳定引用语法保持兼容。
