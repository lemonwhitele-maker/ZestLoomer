# Loom · 织机

**让 AI 围绕整本小说持续协作，正式修改由你确认，作品保存在本地。**

Loom 是一个以小说作品为中心的桌面写作工具。正文、大纲、人物、设定、速记与 AI 对话放在同一个工作区：你可以直接写作，也可以让 Agent 查阅书内资料、讨论情节、检查前后关系，并提出可审阅的修改。

当前版本为 **`0.1.0-beta.2`，Windows x64 内测版**。已提供可直接安装的 `.exe`，无需安装开发环境；尚无代码签名或自动更新，其他平台尚未完成验收。

## Loom 希望解决什么问题

长篇写作需要持续维护大量信息。正文不断增长，人物经历和世界规则分散在不同文档中；讨论中冒出的构想不一定已经成为情节，过去的建议也可能已经被作者放弃。写作工具需要帮助作者保存这些内容、找到依据，并清楚地区分构想和正式修改。

Loom 将日常创作组织成一条连续的流程：

1. **记录与写作**：写正文，把尚未确定的想法放进速记，用人物、设定和大纲维护资料。
2. **阅读与讨论**：在书内查找信息，让 Agent 按任务阅读原文，讨论人物动机、情节衔接和创作方向。
3. **形成提案**：需要新建或修改内容时，先展示候选文本和前后对照。
4. **作者确认**：检查内容后接受或拒绝；目标版本已经变化时，旧提案不能直接覆盖新稿。

讨论可以停留在讨论阶段。你不必接受 AI 建议，也不需要配置 AI 才能继续写作。

## 围绕作品持续协作的 AI

Agent 是工作区内的 AI 对话助手。它可以根据任务定位、搜索和阅读当前作品的资料，也可以为正文、人物、设定、大纲和速记提出新建或修改方案。

- 为情节讨论、人物梳理或正文润色建立独立会话，支持改名和归档。
- 每个会话可以跟随默认模型配置，也可以选择指定配置。
- 发送前检查附带的文档位置和选区，发送后保留当时的上下文记录。
- 查看读取次数、任务阶段、提案与运行明细，并通过来源入口回到文档核对。
- 写入先产生提案；接受后写入，拒绝则不应用。已应用提案仅在版本条件允许时撤销。
- 失败或取消后可以编辑请求再试；较早讨论会整理为会话记忆，不能自动视作书稿事实。

## AI 协作案例

下面是可自行调整的请求示例，不是软件已经完成的分析结论。建议明确目标、范围和是否允许提出修改。

### 检查人物与正文是否一致

> 请阅读林昕的人物资料以及第1章至第3章，检查入职经历、技术经验和做事方式是否前后一致。列出依据和疑点，区分明确矛盾与需要作者确认的地方，先不要修改。

适合先核对来源，再决定是否补写资料或调整正文。人物名称匹配只是线索，最终结论仍应回到原文确认。

### 从速记整理创作方向

> 请阅读当前速记，把内容分成已经明确的构想、互相冲突的备选方案和仍需讨论的问题。先给我整理结果，未确认的内容不要写成人物事实。

如果认可整理方向，再要求生成大纲或速记提案。讨论记录不应直接替代正式设定。

### 润色当前选区

> 只润色我选中的这一段，增加办公室环境的细节，保持人物态度、事件顺序和信息量不变。不要修改选区外的内容，请给出修改提案。

先选中文字，在「发送上下文」确认附带选区原文，再发送。提案出现后核对修改范围，而不是只看最后一句总结。

### 为下一章拟定方案

> 请阅读第7章、相关人物资料和全书总纲，为第8章提出三种推进方向。每种说明承接线索、主要冲突和章末落点，先讨论，不创建正文。

确定方案后，再要求起草并生成正文提案。如果任务资料很多，可先限定章节范围，分阶段推进。

## 快速上手

安装后打开 Loom，按下面的顺序体验一次从讨论到落稿的协作：

1. 点击「新建作品」，输入书名并选择保存位置；已有 Loom 作品可直接打开。
2. 在「正文」新建章节，写入一段内容；在「人物」「设定」或「速记」中补充任务需要的背景。
3. 打开「设置 → AI 接入」，填写模型配置，分别测试连接与工具调用，再保存。
4. 点击「边写边聊」并新建对话，让 AI 先阅读相关资料、讨论问题。发送前展开「发送上下文」，核对当前文档、选区和模型。
5. 确定方向后，要求生成修改提案；查看前后对照，接受或拒绝，以实际文档与保存状态确认结果。
6. 通过「设置 → 作品与备份」保存一份完整备份，再继续下一轮创作。

不配置 AI 也可以使用本地写作功能。详细步骤见 [Loom 使用指南](docs/USER-GUIDE.md)，开发者启动方式见 [从源码运行](#从源码运行)。

## AI 接入

在「设置 → AI 接入 → Agent API」创建配置，填写配置名称、API 地址、模型和密钥。

当前实现使用 **OpenAI Chat Completions 兼容接口**，可以填写基础地址或完整 `/chat/completions` 地址。模型除了能聊天，还需要支持该接口的工具调用。获取不到模型列表时仍可手动填写模型标识。

点击「测试连接」和「测试工具调用」分别验证，再点击「保存 Agent 配置」。测试使用当前填写的参数，不自动保存，也不读取作品。第一份配置自动成为默认配置；以后保存备用配置不会自动切换默认项。

「模型容量与推理设置」用于填写服务实际支持的容量、输出限制和推理强度。容量估算不是实际账单；不确定推理参数是否受支持时，先保留「服务默认」。

「工具 API」用于自动生成对话标题，复用已保存配置；「Agent 偏好」可调整提案对照显示，并开启默认关闭的实验性目标改写。两者可能增加模型请求，详见 [使用指南中的 AI 配置](docs/USER-GUIDE.md#ai-配置)。

## 主要能力

### 一个作品，五类文档

| 分类 | 适合保存什么 | 编辑方式 |
| --- | --- | --- |
| 正文 | 章节内容、正式叙事 | 纯文本；双换行与段首视觉缩进 |
| 速记 | 灵感、备选桥段、待讨论问题 | Markdown 源码；可以有多篇 |
| 人物 | 定位、外貌、状态、事实与经历 | Markdown 源码；可选基础模板或空白 |
| 设定 | 地点、组织、规则、物品等资料 | Markdown 源码；可选基础模板或空白 |
| 大纲 | 全书规划、阶段目标、章节安排 | Markdown 源码；支持调整顺序 |

五类文档共用编辑、自动保存、历史和回收流程。Markdown 目前以源码显示，不提供渲染预览；正文中的视觉缩进和名称高亮不会写入原文。

### 面向长篇的章节管理

- 在列表开头、末尾或指定章节前后创建新章。
- 使用自由标题、阿拉伯数字编号或汉字编号，设置起始号、后缀、补零和自定义模板。
- 批量逐行填写标题，或按数量创建，提交前查看最终名称。
- 通过上下移动、拖拽或多选「移到…」调整顺序。
- 「整理顺序」与「编号与命名」分开处理：可以只移动章节，也可以单独统一标题格式。
- 查看章节字数、全书正文总字数和章节目标进度；快速进入上一章或下一章。

### 编辑、查找与资料关联

- 当前文档查找和替换，列表按标题筛选。
- `Ctrl+P` 快速打开文档，或切换到全书全文搜索并定位到命中行。
- 插入文档引用，`Ctrl+点击` 跳转，`Alt+←` 返回原文位置。
- 在正文中高亮人物名称、设定名称及已保存的别名，帮助识别相关资料。
- 记住文档阅读位置与选区；切回分类时恢复该分类上次阅读的文档。
- 支持专注写作、收起列表、展开 Agent、拖动面板宽度，以及浅色／深色／跟随系统主题。

### 自动保存、历史与恢复

自动保存负责日常落盘；草稿恢复处理未完成的编辑；历史版本用于对照和恢复已保存内容。它们与完整备份共同组成不同层次的恢复方式。

发生外部修改冲突时，当前输入会保留，界面提供两份内容对照，由你选择继续使用磁盘版本，还是保存当前输入。恢复历史会产生一个新的保存版本，并保留恢复前的内容。

每个分类有独立回收站，回收文档可以只读查看并恢复，已有稳定引用仍可打开它。目前不提供永久删除或自动清理。

### 导出与完整备份

「导出」用于输出当前文档；「导出全部正文」用于按章节顺序生成文本稿；「备份完整作品」复制整部作品及工作数据，并核对文件字节是否一致。**交稿请用导出，换电脑或留存恢复点请用完整备份。**

## 项目发展脉络

Loom 的创作方向沿着 **51mazi → 51mazi_chatbox → Loom** 逐步形成。

- **51mazi** 提供了本地小说写作的基础，也成为后续探索的起点。
- **51mazi_chatbox** 在这一基础上把重点放到围绕整本书持续进行的 AI 协作：查阅资料、讨论创作、生成提案，由作者确认正式修改。
- **Loom** 延续这些协作经验，以独立品牌重新构建写作工作区，将正文、人物、设定、大纲、速记和 Agent 集中到同一界面，让这套流程成为产品核心。

这条脉络描述的是产品方向和实践经验的演进。Loom 是独立重建项目，不是 51mazi 的官方后续版本；工程来源还包含 51mazi_codex 的历史与配置，具体参考和实现边界见 [来源记录](docs/provenance.md)。感谢原项目为本地写作和后续探索提供的基础。

## 数据与备份

作品目录包含五类文档和 `.workspace` 工作数据，`book.json` 用来标识 Loom 作品。Windows 应用设置默认位于 `%APPDATA%\Loom`，与书稿分开。

| 内容 | 主要位置 | 搬迁时注意 |
| --- | --- | --- |
| 正文、人物、设定、大纲、速记 | 用户选择的作品目录 | 保留整个作品目录结构 |
| 历史、恢复、回收站、会话、提案和日志 | 作品目录的 `.workspace` | 不要只复制当前正文 |
| 界面设置、作品列表、API 配置 | 应用配置目录 | 完整作品备份不含应用 API 密钥 |

作品备份会在所选位置创建带时间标识的新目录。恢复时，将完整备份放到合适的位置，再通过「打开作品」选择含 `book.json` 的目录。目前没有单独的备份恢复向导。

基础写作在本地完成。使用 AI 时，用户输入、选区、会话上下文及按任务读取的书内资料会发送到所配置的服务；关闭「附带当前文档位置」并不会禁止 Agent 根据任务读取其他书内资料。

API 密钥通过 Electron 的系统加密存储能力保存。不要依赖复制配置目录在另一台电脑自动恢复密钥；搬迁后应重新核对接入配置。

「导出本轮日志」会包含实际书稿、对话、工具结果和模型请求内容。实现不记录 API 鉴权密钥，但日志仍可能含私人文字，提交反馈前请检查。

## 从源码运行

准备 Node.js 22 和 npm，在当前目录执行：

```sh
npm ci
npm run dev
```

首次安装会下载依赖和 Electron。`.npmrc` 配置了 Electron 下载镜像，若下载异常，检查网络和镜像配置。

构建与预览：

```sh
npm run build
npm start
```

`build` 生成 `out/` 中的应用构建产物。在 Windows 上执行以下命令生成安装包：

```sh
npm run package:win
```

该命令生成第三方声明、构建应用，再使用锁定的 electron-builder / NSIS 打包。中间产物在 `dist/`，可交付文件自动整理到 `../安装包/Loom-<版本>/`，并生成 `SHA256SUMS.txt`。配置见 `electron-builder.json`，本命令不上传或发布到远端。

开发验证：

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
# 按以上顺序执行
npm run verify
```

窗口测试使用本地 Electron，无需额外安装浏览器，需要能正常启动桌面进程的环境。测试作品和配置保存在 `.test-artifacts/`；受限环境中的启动失败不能当作功能通过，也不能仅凭这一点认定应用本身有缺陷。

技术栈为 Electron、Vue 3、TypeScript、CodeMirror 和 electron-vite，精确依赖以锁文件为准。

```text
src/main/       作品存储、桌面操作与 Agent
src/preload/    桌面通信桥接
src/renderer/   工作区界面与编辑器
src/shared/     类型、模板和共用逻辑
tests/          单元测试与窗口测试
scripts/        性能与发布辅助工具
docs/           使用指南、设计和来源记录
```

## 当前限制

- 已提供 Windows x64 内测安装包；尚无签名或自动更新，独立电脑与跨版本升级验收仍待完成。
- 当前按 Windows x64 内测准备；不能由源码可构建推断其他平台已受支持。
- Markdown 是源码编辑；正文采用纯文本，不提供富文本排版和 Markdown 预览。
- 正文章节列表目前是平铺结构，没有分卷界面。
- Agent 的书内检索不是联网搜索；实际兼容模型和长期写作稳定性仍需分别验证。
- 会话输入草稿在当前运行期间按会话保留，尚不承诺关闭重启后恢复。
- 回收站没有永久删除与自动清理，完整日志仅保留每个会话最近一轮；不等于保留每一轮完整请求日志。
